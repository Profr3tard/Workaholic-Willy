# OPTIONAL — exact mesh-vs-mesh self-collision backend (H3.9f built it; H3.9g migrated the engine to Coal).
# Engine: COAL preferred, python-fcl fallback (both guarded; default backend='capsule' needs NEITHER).
#
# ``self_collision.backend='fcl'`` runs exact closest-DISTANCE on the real UR5e collision meshes (bundled,
# DH-baked, vertex-validated <0.15mm) instead of the capsule proxy — which was measured wrong in BOTH
# directions (false-NEGATIVE forearm|wrist_3 25mm skipped by ``_should_skip_pair``; false-POSITIVE
# link_2|link_5 from the fat default radius).
#
# H3.9g swapped the engine to Coal (the maintained hpp-fcl successor) — a behavior-IDENTICAL swap: same
# BVH meshes, same pairs, same thresholds, same distance query. Proven byte-identical to python-fcl at the
# distance level (natural 19.640mm, flipped 0.0mm, park 19.224mm — the values the guard triggers on); Coal
# is ~1.5x faster on this workload (future RT-budget headroom). Coal's extra features (swept-sphere,
# contact patches, Nesterov) are deliberately NOT used here.
#
# Coal has NO pip wheel (the cmeel/Gepetto stack is Linux/macOS-first; on Windows use conda-forge):
#     conda install coal -c conda-forge          # or micromamba create -p <env> -c conda-forge coal python=3.11
# For a NON-conda interpreter on Windows (the project .venv, or the Isaac standalone python) point
# WILLY_COAL_PREFIX at that conda env — the backend then injects its DLL dir + site-packages and imports
# Coal (it works against the host's own numpy, 1.x or 2.x):
#     set WILLY_COAL_PREFIX=ext_deps\coal_env
#
# python-fcl IS pip-installable (ships Windows wheels) and is the guarded FALLBACK when Coal is absent:
python-fcl==0.7.0.11
#
# If neither engine (nor the mesh bundle) is importable, ``make_backend`` returns None and the guard falls
# back to the capsule path — no hard crash. Both engines are excluded from CI (no universal wheels) so
# runners without them stay green.
